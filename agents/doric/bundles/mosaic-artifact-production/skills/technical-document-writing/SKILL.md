# Technical Document Writing

## Purpose

Produzir conteúdo técnico executável e verificável sem pressupor conhecimento que não foi apresentado.

## Use this skill when

- o usuário pede guia, procedimento, documentação de arquitetura ou instruções técnicas.
- o resultado será consumido por pessoas que precisam executar ou manter um sistema.
- há requisitos e evidências suficientes para redigir o conteúdo.

## Do not use this skill when

- o objetivo é apenas persistir conteúdo já aprovado em arquivo.
- o pedido exige um README de instalação com estrutura mais específica.
- não há informações mínimas sobre o sistema ou procedimento.

## Procedure

1. Defina audiência, objetivo e resultado que o leitor deve conseguir obter.
2. Apresente contexto e pré-requisitos antes das etapas.
3. Organize o procedimento em ordem executável, com comandos ou exemplos somente quando sustentados.
4. Explique decisões que alteram o uso; omita histórico sem efeito operacional.
5. Inclua uma forma de validar o resultado.
6. Registre limitações, incompatibilidades e próximos passos necessários.
7. Revise termos, identificadores e referências para consistência.

## Completion

O documento permite ao público-alvo compreender e executar o procedimento, verificar o resultado e reconhecer limites relevantes.
